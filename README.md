# نظام إدارة الدروس (Offline-first Class Management)

## التثبيت

```bash
npm install dexie dexie-react-hooks react-hook-form qrcode.react html5-qrcode
```

(Tailwind CSS يُفترض أنه مُهيأ مسبقاً في مشروعك. إن لم يكن كذلك: `npx tailwindcss init -p`)

قاعدة البيانات (`db.js`) تُنشأ تلقائياً في IndexedDB أول مرة يفتح فيها المتصفح `db.js`
(لا حاجة لأي إعداد إضافي). كل الجداول الخمسة موجودة:
`students, groups, attendance, tasks, payments`.

## شاشة إضافة طالب (`AddStudent.jsx`)

```jsx
import AddStudent from './components/AddStudent';

<AddStudent
  onDone={() => {
    /* التنقل رجوعاً للوحة التحكم */
  }}
/>;
```

- النموذج مبني بـ `react-hook-form` (تحقق فوري من الحقول: الاسم مطلوب، رقم ولي الأمر
  مطلوب بصيغة صحيحة، رقم هاتف الطالب اختياري، واختيار المجموعة إلزامي من قائمة
  المجموعات النشطة فعلياً في القاعدة).
- بعد الحفظ في `db.students`، تنتقل الشاشة تلقائياً لعرض الكارنيه باستخدام
  `QRCodeCanvas` من مكتبة `qrcode.react`، والقيمة المُشفَّرة هي نفس `qrCode`
  المولّد تلقائياً في `db.js` (وهي القيمة التي ستقرأها الكاميرا لاحقاً في شاشة الحضور).
- **طباعة الكارنيه**: تستخدم `window.print()` مع CSS مخصص (`@media print`) يُخفي كل
  شيء في الصفحة عدا عنصر `#printable-card`، فتخرج طباعة نظيفة للكارنيه فقط.
- **حفظ كصورة**: يرسم الكارنيه كاملاً (شريط علوي + QR + اسم + مجموعة) على
  `<canvas>` مؤقت ثم يصدّره كملف PNG قابل للتحميل مباشرة — مفيد لإرساله عبر واتساب
  أو طباعته من مكان آخر لاحقاً.

## شاشة مسح الحضور (`AttendanceScanner.jsx`)

```jsx
import AttendanceScanner from './components/AttendanceScanner';

<AttendanceScanner
  onDone={() => {
    /* التنقل رجوعاً للوحة التحكم */
  }}
/>;
```

- تعمل الكاميرا الخلفية تلقائياً عبر `facingMode: "environment"` من `html5-qrcode`
  (أوثق من تحديد جهاز كاميرا معيّن يدوياً، ويعمل بثبات أكبر عبر أجهزة الهاتف المختلفة).
- **الصلاحيات**: لو رفض المستخدم إذن الكاميرا، تظهر رسالة واضحة بخطوات التفعيل من
  إعدادات المتصفح. لو تعذّر التشغيل لسبب آخر (كاميرا مستخدَمة من تطبيق آخر، الموقع
  غير مُقدَّم عبر HTTPS...) تظهر رسالة توضيحية مختلفة.
- **منع التكرار**: عند كل مسح ناجح يتم استدعاء `scanner.pause(true)` فوراً (لا ينتظر
  أي شيء)، ثم بعد إتمام المعالجة (البحث + الحفظ) يُعاد `scanner.resume()` تلقائياً
  بعد ثانية واحدة بالضبط (`SCAN_COOLDOWN_MS`). كما يوجد `isProcessingRef` يمنع معالجة
  أي مسح إضافي يصل أثناء المعالجة الجارية.
- **التحقق من التكرار في القاعدة**: قبل إضافة أي سجل حضور، يتحقق الكود من الفهرس
  المركّب `[studentId+date]` في `db.attendance` (نفس الفهرس المُعرَّف في `db.js`)،
  فإن وُجد سجل بالفعل يظهر تنبيه أصفر "تم تسجيل حضوره مسبقاً" بدل تكرار الإضافة.
- **التغذية الراجعة**: Toasts ملوّنة (أخضر = نجاح، أصفر = تنبيه/تكرار، أحمر = خطأ)
  تظهر أعلى الشاشة وتختفي تلقائياً بعد ~2.8 ثانية بدون أي تدخل من المدرس، فتبقى
  الكاميرا جاهزة للكارت التالي مباشرة.
- عدّاد "تم تسجيلهم في هذه الجلسة" يعطي المدرس نظرة سريعة أثناء استقبال الطلاب.

### تحديث في `db.js` (نسخة Schema رقم 2)

هذه الشاشة احتاجت توسيعاً بسيطاً وضرورياً في القاعدة (أضفته في `db.js` ضمن `db.version(2)`):

- **`tasks`** أصبح يحمل الآن `groupId` و`date` و`kind` (`'participation' | 'homework' | 'exam'`)،
  مع فهرس مركب `[studentId+date+kind]`. هذا ضروري لأن بند "تفاعل يوم الأحد" مختلف عن
  "تفاعل يوم الثلاثاء" لنفس الطالب — الجدول القديم لم يكن يميّز بينهما بتاريخ.
- **`sessions`** جدول جديد: `groupId, date, hasExam, examTotal` مع فهرس مركب `[groupId+date]`،
  يخزّن إعدادات كل حصة (هل بها امتحان؟ وما الدرجة النهائية لورقته؟) بحيث تُسترجع تلقائياً
  عند العودة لنفس المجموعة والتاريخ لاحقاً.
- Dexie يطبّق الترقية تلقائياً عند فتح التطبيق (لا حاجة لأي كود هجرة يدوي، لأن الإضافات
  حقول/فهارس جديدة فقط ولا تحذف بيانات قديمة).

### إعدادات النقاط العامة (Global Points)

مخزّنة في `localStorage` تحت المفتاح `cms_points_settings` بالقيم الافتراضية
`{ attendance: 4, participation: 1, homework: 2, exam: 5 }`، ولا تظهر للتعديل في هذه
الشاشة كما طلبت. عند الحاجة لاحقاً لشاشة "إعدادات عامة" لتعديلها، يكفي قراءة/كتابة
نفس المفتاح.

### منطق الحساب المطبَّق بالضبط

- **بدون امتحان**: المتاح = 4+1+2 = 7 نقاط. حاضر/مستثنى = 4، جيد/مستثنى = 1، أنجز/مستثنى = 2.
  `التقييم = (المكتسب/7) × 10`.
- **بامتحان**: المتاح = 12 نقطة. نقاط الامتحان = `(درجة الطالب / الدرجة النهائية) × 5`،
  أو 5 كاملة إن كان مستثنى. `التقييم = (المكتسب/12) × 10`.
- الحساب **لحظي بالكامل**: كل حقل (Select/Checkbox/Input) يكتب مباشرة في Dexie عبر دوال
  `upsertAttendance` / `upsertTask` / `upsertSession`، و`useLiveQuery` يعيد حساب الدرجة
  فوراً مع أي تغيير — بدون أي زر "حفظ" منفصل.

### رسالة الواتساب الديناميكية

`buildWhatsAppLink` تبني الرسالة بالضبط بالصيغة التي طلبتها (الحضور، الواجب، التفاعل،
ثم التقييم العام)، وتُخفي سطر الامتحان بالكامل عندما تكون الحصة بلا امتحان. عند وجود
امتحان، يُضاف سطر إضافي بالدرجة (أو "مستثنى") قبل سطر التقييم النهائي.

## شاشة المدفوعات (`Payments.jsx`)

```jsx
import Payments from './components/Payments';

<Payments
  onDone={() => {
    /* التنقل رجوعاً للوحة التحكم */
  }}
/>;
```

- **فلترة الشهر**: قائمة أشهر مبنية تلقائياً حول الشهر الحالي (6 قبل و6 بعد) بصيغة
  `YYYY-MM`، معروضة بأسماء عربية مثل "أغسطس 2026". القيمة الافتراضية `currentMonthStr()`
  من `db.js` — نفس الصيغة المستخدمة في حقل `month` بجدول `payments`.
- **حالة الدفع لحظية بالكامل**: يُقرأ `db.payments` عبر `useLiveQuery` مفلتراً بـ `month`،
  ثم يُطابَق محلياً مع طلاب المجموعة عبر `studentId`. أي عملية "تسديد" تُحدّث الشارة
  الخضراء فوراً في كل مكان (بما فيها بطاقة الإجماليات) بدون أي refresh يدوي.
- **بطاقة الإجماليات** أعلى الشاشة: إجمالي المُحصَّل من هذه المجموعة في هذا الشهر تحديداً
  (وليس كل المجاميع)، وعدد الدافعين مقابل إجمالي طلاب المجموعة.
- **رسالة الواتساب** تتغيّر تلقائياً حسب الحالة: تذكير بالدفع (أصفر) قبل السداد، إيصال
  استلام بالمبلغ (رمادي) بعد السداد — بنفس الصياغة المطلوبة حرفياً.
- لا حاجة لأي تعديل إضافي على `db.js`؛ الفهرس المركب `[studentId+month]` كان موجوداً
  أصلاً من التصميم الأول.

## شاشة إدارة المجموعات (`Groups.jsx`)

```jsx
import Groups from './components/Groups';

<Groups
  onDone={() => {
    /* التنقل رجوعاً للوحة التحكم */
  }}
/>;
```

هذه الشاشة هي "نقطة البداية" الفعلية للتطبيق — بدونها لا يمكن اختبار أي شاشة أخرى،
لأن كل الشاشات السابقة (إضافة طالب، الحضور، التقييم، المدفوعات) تعتمد على وجود
مجموعات فعلية في `db.groups`.

- **إضافة مجموعة**: نموذج `react-hook-form` بسيط (اسم المجموعة + السنة الدراسية)،
  يُضاف مباشرة بـ `isArchived: 0`.
- **عدد الطلاب لكل بطاقة**: بدل تنفيذ استعلام Dexie منفصل لكل بطاقة مجموعة (وهو
  نمط شائع لكنه غير كفء)، نجلب كل الطلاب النشطين مرة واحدة عبر `useLiveQuery`
  ثم نجمّعهم محلياً في `Map` بـ `groupId` — استعلام واحد للقاعدة بدل استعلام لكل بطاقة.
- **الأرشفة مع تأثير Cascade**: تُنفَّذ داخل `db.transaction("rw", db.groups, db.students, ...)`
  بحيث يتم تحديث المجموعة نفسها (`isArchived: 1`) وكل طلابها (`.where("groupId").equals(id).modify(...)`)
  كعملية واحدة ذرية (atomic) — إما تنجح كلها معاً أو تفشل كلها معاً، فلا يحدث أبداً
  أن تُؤرشف المجموعة بينما يبقى طلابها نشطين بالخطأ.
- **نافذة التأكيد**: مكوّن `ConfirmDialog` مخصص بـ Tailwind (وليس `window.confirm` الافتراضي
  في المتصفح) لضمان اتساق التصميم، ويوضح صراحةً أن الأرشفة ستشمل طلاب المجموعة أيضاً.
- **تبويب "عرض السجل التاريخي"**: يعرض المجموعات المؤرشفة فقط للقراءة (بدون أي أزرار
  إجراء)، مع عداد صغير بجانب كل تبويب يوضح عدد المجموعات في كل حالة.

### ملاحظة إصلاح مهمة (isArchived)

لاحظت أن `db.js` كان يخزّن `isArchived` كقيمة منطقية أصلية، بينما كل استعلامات
الشاشات (`Dashboard`, `Evaluations`, `Payments`...) تبحث بـ `.equals(0)` / `.equals(1)`.
السبب: **IndexedDB لا يدعم القيم المنطقية (true/false) كنوع فهرسة موثوق** عبر كل
المتصفحات، فتخزين `true/false` مباشرة قد يجعل السجل غير مفهرَس فعلياً وتفشل
الاستعلامات بصمت (بدون أي خطأ ظاهر). عالجت هذا بتوحيد التخزين على شكل أرقام
(`0` أو `1`) داخل الـ hooks في `db.js`، بحيث تعمل كل الاستعلامات في كل الشاشات
بشكل صحيح ومتسق.

## الربط النهائي (`App.jsx`)

```jsx
// src/main.jsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';
import './index.css'; // ملف Tailwind (@tailwind base/components/utilities)

ReactDOM.createRoot(document.getElementById('root')).render(<App />);
```

- **التنقل**: حالة React بسيطة (`useState`) بدل `react-router-dom` — التطبيق شاشة واحدة
  (SPA) بدون حاجة لعناوين URL قابلة للمشاركة، فالحالة البسيطة أخف وأنسب لتطبيق PWA
  محلي بالكامل.
- **شريط سفلي**: الرئيسية / تسجيل الحضور / تقييم الحصة / المدفوعات (4 شاشات الاستخدام اليومي).
- **قائمة جانبية (Hamburger)**: إدارة المجموعات / إضافة طالب (شاشات إدارية أقل تكراراً)،
  تنزلق من جهة اليمين (مناسبة لاتجاه RTL) مع طبقة خلفية معتّمة تُغلق القائمة عند الضغط عليها.
- **Header علوي ثابت (sticky)**: اسم التطبيق "مساعد المدرس الذكي" + عنوان الشاشة الحالية،
  يتحدّث تلقائياً حسب `view` النشطة.
- كل الشاشات مربوطة عبر `onDone` للعودة للرئيسية، وشاشة `Dashboard` تحديداً مربوطة بزرَّي
  "بدء حصة جديدة" (→ شاشة المسح) و"أرشفة نهاية العام" (→ شاشة المجموعات).

## تهيئة PWA (العمل بدون إنترنت + التثبيت على الهاتف)

### 1) التثبيت

```bash
npm create vite@latest class-management -- --template react
cd class-management
npm install dexie dexie-react-hooks react-hook-form qrcode.react html5-qrcode
npm install -D tailwindcss postcss autoprefixer vite-plugin-pwa
```

انسخ كل الملفات المرفقة (`src/db`, `src/lib`, `src/components`, `src/App.jsx`,
`src/index.css`, `vite.config.js`, `tailwind.config.js`, `index.html`,
`public/manifest.json`) داخل مجلد المشروع بنفس المسارات. **لاحظ إن `tailwind.config.js`
و`src/index.css` مرفقان جاهزان بالفعل** — مفيش حاجة لتشغيل `npx tailwindcss init`
يدوياً ولا كتابة ملف CSS من الصفر.

### 2) ربط index.css بنقطة الدخول

```jsx
// src/main.jsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';
import './index.css'; // ضروري — هنا تُفعَّل توجيهات Tailwind الأساسية

ReactDOM.createRoot(document.getElementById('root')).render(<App />);
```

### 3) أيقونات التطبيق

أضف 3 صور PNG داخل `public/icons/`:
`icon-192.png` (192×192)، `icon-512.png` (512×512)، `icon-maskable-512.png`
(512×512 بهامش أمان ~10% حول الشعار، لأن بعض أنظمة أندرويد تقصّ الحواف). أي أداة
تصميم بسيطة (Canva، Figma) كافية لتوليدها من شعارك.

### 4) التشغيل محلياً

```bash
npm run dev
```

### 5) البناء للإنتاج (مطلوب لتفعيل PWA فعلياً — الـ Service Worker لا يعمل في وضع dev)

```bash
npm run build
npm run preview
```

`vite-plugin-pwa` (المُهيَّأ في `vite.config.js` المرفق) يولّد Service Worker تلقائياً
عبر Workbox، ويخزّن كل ملفات JS/CSS/HTML مؤقتاً بحيث يعمل التطبيق بالكامل بدون إنترنت
من الفتحة الثانية فصاعداً (الفتحة الأولى تحتاج اتصالاً لتنزيل الملفات وتخزينها).

> **بديل Next.js**: إن فضّلت Next.js بدل Vite، استخدم حزمة `next-pwa` بنفس الفكرة
> (تسجيل Service Worker تلقائياً + حقن manifest)، لكن الإعداد المرفق هنا مبني على Vite
> لأنه أخف وأسرع لتطبيق محلي بحت بدون حاجة لـ Server-side Rendering.

### 6) تثبيت التطبيق على الهاتف

بعد رفع نسخة `npm run build` على أي استضافة تدعم HTTPS (حتى استضافة ثابتة مجانية
مثل GitHub Pages أو Netlify كافية — لا حاجة لخادم حقيقي لأن كل البيانات محلية)،
أو تشغيلها على شبكة الواي فاي المحلية عبر `npm run preview -- --host`:

**أندرويد (Chrome)**: افتح رابط التطبيق ← اضغط قائمة (⋮) ← "إضافة إلى الشاشة الرئيسية"
أو ستظهر رسالة تلقائية "تثبيت التطبيق" أسفل الشاشة.

**آيفون (Safari)**: افتح رابط التطبيق ← اضغط زر المشاركة (المربع بالسهم) ← "إضافة إلى

IndexedDB يعمل بشكل طبيعي، لكن قد يحتاج المدرس فتح التطبيق بين الحين والآخر لتفادي
حذف iOS للبيانات المخزَّنة لتطبيقات الويب غير المستخدَمة لفترة طويلة جداً — لذا زر
"نسخ احتياطي" الأسبوعي في لوحة التحكم مهم بشكل خاص على iOS).

## دعم RTL

- `index.html` يحمل `dir="rtl" lang="ar"` على عنصر `<html>` نفسه، فكل عناصر واجهة
  المتصفح الأصلية (شريط التمرير، القوائم المنسدلة، محاذاة النصوص الافتراضية) تُصبح
  RTL تلقائياً من أول تحميل — لا "ومضة" اتجاه خاطئ (FOUC) قبل تحميل React.
- كل شاشة تضع `dir="rtl"` أيضاً على العنصر الجذري الخاص بها (تكرار غير ضار، يضمن
  عمل الشاشة بشكل صحيح حتى لو استُخدمت مستقبلاً خارج `App.jsx`، مثلاً داخل Storybook).
- Tailwind + CSS Flexbox/Grid يعكسان الاتجاه تلقائياً حسب خاصية `dir` في المتصفح
  (بدون أي إعداد أو Plugin إضافي)، لذلك كل الـ `flex`/`gap`/`justify-between` في كل
  الشاشات المرفقة تعمل بصورة صحيحة في RTL كما هي.

## تحديث نظام التقييم — النجوم ⭐️ (`Evaluations.jsx`)

- **تخزين النجوم**: حقل `stars` (رقم من 0 إلى 5) بدل الحقل النصي `value` القديم

  قديمة أُدخلت قبل هذا التحديث (بالنظام النصي القديم) لن تُقرأ بشكل صحيح كنجوم — ستظهر
  كصفر نجوم افتراضياً. هذا متوقّع لأن النظامين مختلفان جوهرياً في طريقة التسجيل، ولا

- **تفاعل النجوم**: النقر على نجمة يحدد التقييم عندها، والنقر على "نفس آخر نجمة محددة"

## نظام قوالب الواتساب المركزي (`src/lib/whatsappTemplates.js`)

ملف مشترك جديد تستخدمه شاشتا `Evaluations.jsx` و`Payments.jsx` (بدل الرسائل المكتوبة
داخل كل شاشة سابقاً)، وتديره شاشة `Settings.jsx`:

- **3 فئات** بالضبط كما طلبت: `payment_reminder`، `payment_confirmation`، `evaluation`،
  كل فئة تُنشأ بقالب "افتراضي" جاهز من أول تشغيل.
- **دوال الإدارة**: `addTemplate`, `updateTemplate`, `deleteTemplate`, `setDefaultTemplate`
  — حذف القالب الافتراضي يُرقّي تلقائياً أول قالب متبقٍ في نفس الفئة ليصبح الافتراضي
  الجديد (لا تبقى أي فئة بلا قالب افتراضي طالما بها قالب واحد على الأقل).
- **10 متغيرات ديناميكية** بالضبط كما طلبت (`TEMPLATE_VARIABLES`)، و`fillTemplate(body, vars)`

- **الشاشات تقرأ القالب الافتراضي مباشرة عند كل ضغطة على زر الواتساب** عبر
  `getDefaultTemplate(category)` — أي تعديل تجريه على القالب الافتراضي من الإعدادات
  ينعكس فوراً في الرسائل التالية بدون أي إعادة تشغيل.
- **ملاحظة سلوكية مهمة بخصوص شاشة التقييم**: بما أن الرسالة الآن نص قالب واحد ثابت
  (وليس أسطراً تُبنى ديناميكياً في الكود كما كانت سابقاً)، فمتغيرات الامتحان
  (`[درجة_الامتحان]`, `[الدرجة_النهائية_للامتحان]`) تُستبدَل بـ"لا يوجد امتحان" تلقائياً
  عند عدم وجود امتحان في الحصة، بدل حذف السطر بالكامل كما كان يحدث في النسخة المُبرمَجة
  يدوياً سابقاً. إن أردت إخفاء السطر بالكامل بدل ظهور "لا يوجد امتحان"، يمكنك ببساطة
  عدم كتابة سطر الامتحان في القالب الافتراضي لفئة "متابعة التقييم" من الأساس، أو صياغته
  بحيث يبدو طبيعياً في الحالتين.

مُدرَجة الآن ضمن القائمة الجانبية (Sidebar) في `App.jsx` مع أيقونة ترس مخصصة. تحتوي قسمين:

### 1) إدارة قوالب الواتساب

- تبويبات للفئات الثلاث، وكل قالب يظهر مع Radio button لتحديده كافتراضي، وزرَي
  تعديل/حذف. حذف آخر قالب في الفئة معطَّل (زر باهت) لمنع ترك الفئة بلا أي قالب.
- محرّر القالب (نافذة منبثقة) فيه حقل اسم + `textarea` للنص + شرائح (Chips) لكل
  متغيّر من الـ 10 — الضغط على أي شريحة يُدرِج المتغيّر **في موضع المؤشر داخل النص**
  (وليس في نهايته فقط)، عبر تتبّع `selectionStart`/`selectionEnd` للـ `textarea`.

### 2) النسخ الاحتياطي والاستيراد

- **تصدير**: يستخدم `exportAllData()` الجديدة في `db.js` (تُصدِّر الجداول الستة كاملة
  بما فيها `sessions`)، بنفس المنطق المستخدم في زر التصدير بلوحة التحكم — تم توحيد
  الدالتين لتفادي وجود نسختين مختلفتين قد تتباعدان لاحقاً عند إضافة جداول جديدة.
- **استيراد**: زر يفتح منتقي ملفات (`accept="application/json"`)، وبعد اختيار الملف
  تظهر **نافذة تأكيد صريحة** توضح أن هذا سيحذف كل البيانات الحالية ويستبدلها بالكامل.
  عند التأكيد: `importAllData()` تُفرِّغ كل الجداول الستة ثم تُعيد إدخال بيانات الملف
  عبر `bulkPut` **مع الاحتفاظ بنفس قيم `id` الأصلية** — وهذا مهم جداً: لو أعدنا توليد
  `id` جديدة، كانت ستنكسر كل الروابط بين الجداول (مثلاً `studentId` المخزَّن داخل سجلات
  `attendance`/`payments`/`tasks` يشير إلى id قديم لن يعود موجوداً).
- كل العملية تتم داخل `db.transaction("rw", ...)` واحدة تشمل الجداول الستة معاً، فإما
  تنجح عملية الاستيراد بالكامل أو تفشل بالكامل دون ترك القاعدة في حالة منتصفة (Corrupted).

**صراحةً ومهم توضيحه**: التطبيق Offline بالكامل بدون خادم، لذلك تنبيه Push حقيقي

وهذا يتعارض مع فكرة "محلي بالكامل". اللي تم بناؤه هو أفضل تنبيه ممكن Offline:

- **محرّك التنبيهات** في `App.jsx`: يفحص كل 20 ثانية (طالما التطبيق/التبويب مفتوح)

  حضور" (ينقلك مباشرة لشاشة المسح) وزر "تجاهل".

- **إشعار المتصفح الحقيقي (اختياري)**: لو فعّل المدرس إذن الإشعارات من زر

  إشعار نظام حقيقي (`new Notification(...)`) بجانب البانر — يعمل حتى لو
  التطبيق في تبويب آخر أو مصغّر (على أندرويد بثبات أكبر من iOS، حيث تُقيّد
  أبل تنبيهات الويب في الخلفية بشكل عام).
- **إعدادات الإعدادات**: تفعيل/إيقاف كامل + اختيار المدة (5/15/30/60 دقيقة)،

## نظام المواد الدراسية (`src/lib/subjects.js`, `Evaluations.jsx`, `Settings.jsx`)

مصمَّم خصيصاً للمدرّس اللي بيدرّس أكتر من مادة في نفس المجموعة (تفسير/فقه/حديث
مثلاً)، بنفس فلسفة معمارية "خيار عام على مستوى الحصة، قابل للتغيير يوم بيوم"
اللي اقترحتها بنفسك — بالضبط نفس نمط "هل يوجد امتحان اليوم؟" الموجود مسبقاً:

- **الإعدادات**: قسم "المواد الدراسية" الجديد — قائمة نصوص بسيطة (إضافة/حذف)،
  مخزَّنة في `localStorage` تحت `cms_subjects`. **فاضية افتراضياً** — لو
  ما أضفتش أي مادة، اختيار المادة **مش هيظهر خالص** في شاشة التقييم (مفيد
  للمدرّس اللي بيدرّس مادة واحدة ومش عايز خطوة إضافية).
- **`Evaluations.jsx`**: لو القائمة مش فاضية، يظهر Select "المادة" في رأس
  إعدادات الحصة (بجانب المجموعة/التاريخ/الامتحان)، ومربوط بـ `db.sessions`
  بنفس آلية `upsertSession` المستخدمة لـ `hasExam` — فهو **قابل للتغيير يومياً**
  تماماً كما اقترحت، بدون أي تكرار لكل طالب.
- **رسالة الواتساب**: [المادة] أصبح متغيراً متاحاً في محرّر القوالب (شريحة
  جاهزة للإدراج)، ويُستبدَل تلقائياً باسم المادة المختارة لهذه الحصة عند
  الإرسال الفعلي.

## تحسينات UX — "ابدأ الحصة" الذكي + إدارة طلاب المجموعة

### 1) زر "ابدأ الحصة" يظهر فقط في وقته الفعلي

- `getUpcomingSessions` في `schedule.js` بقى بيحسب "الموعد ذو الصلة" مش بس "الموعد
  القادم البحت": لو موعد اليوم فات لكن لسه ضمن `SESSION_ACTIVE_WINDOW_MINUTES` (90
  دقيقة افتراضياً)، يظل يُعتبر الموعد الحالي بدل القفز مباشرة لتكرار الأسبوع الجاي.
  كل عنصر راجع من الدالة معاه `isActive: boolean`.
- **`Dashboard.jsx`**: لما `isActive` تبقى `true`، يظهر زر أخضر "ابدأ الحصة" بدل
  عدّاد الوقت، ويختفي تلقائياً بعد انتهاء الـ 90 دقيقة (لأن الموعد وقتها بيتحسب
  كتكرار الأسبوع القادم، فمش هيبقى `isActive` تاني).
- تقدر تغيّر مدة الـ 90 دقيقة دي بتعديل `SESSION_ACTIVE_WINDOW_MINUTES` في
  `src/lib/schedule.js` لو حابب مدة مختلفة.

### 2) "ابدأ الحصة" ينقلك مباشرة لطلاب المجموعة بدون إعادة اختيار

- زر "ابدأ الحصة" في لوحة التحكم بيستدعي `onStartGroupSession(groupId)` (مُمرَّرة
  من `App.jsx`)، اللي بتحفظ المجموعة وتنقلك مباشرة لشاشة "تقييم الحصة" **ومعاها
  المجموعة مُختارة تلقائياً** (بدل ما تدخل الشاشة وتضطر تفتح القائمة المنسدلة
  وتدوّر على المجموعة بنفسك). التاريخ بيبقى "اليوم" تلقائياً كما هو معتاد.
- `Evaluations.jsx` بقى بيقبل prop اختياري `initialGroupId` لهذا الغرض تحديداً.
- **ملاحظة**: لو دخلت شاشة "تقييم الحصة" من التبويب السفلي العادي (مش من زر "ابدأ
  الحصة")، هتفضل آخر مجموعة بدأت بيها حصة هي المختارة افتراضياً (سلوك مقصود يوفر
  عليك خطوة، مش خطأ).

### 3) الضغط على أي مجموعة يفتح قائمة طلابها القابلة للتعديل (`GroupStudents.jsx`)

مكوّن جديد بالكامل — كان ناقصاً فعلاً من التطبيق: قبل كده مفيش أي طريقة لعرض أو
تعديل بيانات طالب موجود بعد إضافته لأول مرة.

- **الوصول**: اضغط على جسم بطاقة أي مجموعة نشطة في شاشة "إدارة المجموعات" (عدا
  زرَّي "تعديل المواعيد" و"أرشفة المجموعة" اللي فضلوا يشتغلوا مستقلين عن الضغطة دي).
- **لكل طالب في القائمة**: اسم + رقم ولي الأمر + 3 أزرار:
  - **تعديل**: نافذة `react-hook-form` (بنفس نمط شاشة إضافة طالب) لتعديل الاسم،
    رقم هاتف الطالب، رقم ولي الأمر، **ونقل الطالب لمجموعة أخرى** لو حبيت — سجلاته
    القديمة (حضور/تقييم/مدفوعات) بتفضل مرتبطة بيه بغض النظر عن نقل المجموعة.
  - **أرشفة / إلغاء الأرشفة**: تبديل سريع بدون الحاجة لأرشفة المجموعة كلها.
  - **حذف نهائي**: بعد نافذة تأكيد صريحة، يحذف الطالب **وكل سجلاته المرتبطة**
    (حضور، تقييم، مدفوعات) عبر `db.transaction` واحدة — مختلف تماماً عن "أرشفة"
    اللي بتحافظ على البيانات وتخفيها بس. النافذة بتوضح الفرق صراحةً قبل التأكيد.

الحل: استبدلت الاعتماد على ترتيب flex/dir بموضع صريح (`fixed` + `right-0`) للوحة
القائمة، فهي الآن مثبَّتة على اليمين دائماً بغض النظر عن أي تعقيدات في اتجاه المتصفح.

### 3) حذف زر "بدء حصة جديدة" العام من الرئيسية

كان زراً عاماً بيروح لشاشة المسح بدون أي سياق مجموعة، وبقى فعلياً بلا فايدة حقيقية
بعد إضافة أزرار "ابدأ الحصة" لكل مجموعة في قسم "الحصص القادمة" (واللي بتاخدك فعلياً
لشاشة التقييم بالمجموعة الصح). شاشة "تسجيل الحضور" لسه موجودة وسهلة الوصول من شريط
التنقل السفلي زي ما هي، فمفيش أي ميزة اتفقدت.

### 4) شاشة المالية الجديدة (`Finance.jsx`)

مُدرَجة في القائمة الجانبية. لكل مجموعة نشطة، تعرض في شهر مُختار: **المُحصَّل فعلياً**
(من `db.payments` مباشرة)، **المتوقَّع تحصيله** و**المتبقي** (بناءً على حقل "الرسم
الشهري لكل طالب" الجديد على المجموعة × عدد طلابها)، بالإضافة لبطاقات إجمالي عام تجمع
كل المجاميع معاً أعلى الشاشة.

- **مهم**: حساب "المتبقي" يحتاج معرفة القيمة المتوقعة أصلاً، والتطبيق ماكانش فيه أي
  مفهوم "رسم شهري ثابت" من قبل — أضفته كحقل اختياري جديد على المجموعة (`monthlyFee`،
  حقل عادي غير مفهرَس، بدون أي تعديل Dexie schema)، تقدر تحدده من زر "تعديل المواعيد
  والرسوم" في شاشة إدارة المجموعات (نفس الزر اللي كان لتعديل المواعيد بس، وسّعته).
  لو مجموعة معينة معندهاش رسم محدَّد، بتظهر "غير محدَّد" بدل رقم خاطئ، مع تنبيه أصفر
  أعلى الشاشة يوضح إن الإجمالي العام مش شامل هذه المجموعة في حساب المتوقَّع/المتبقي.

### 5) درجة الامتحان في تقرير الواتساب بقت تظهر بصيغة "الدرجة/الدرجة النهائية"

كانت تظهر الرقم بس (مثلاً "25")، دلوقتي بتظهر "25/40" تلقائياً (باستخدام
`examTotal` المُسجَّلة لنفس الحصة)، سواء استخدمت المتغيّر `[درجة_الامتحان]` في القالب.

## إعادة هيكلة شاشة إدارة المجموعات + تبسيط الـ Header العام

### شاشة إدارة المجموعات (`Groups.jsx`) — أعيد بناؤها بالكامل

- **أول ما تفتح الشاشة** تشوف "المجموعات النشطة" مباشرة — مفيش أي فورم ثابت فوق
  بيشغل مساحة قبل ما توصلها.
- **"إضافة مجموعة جديدة"** بقى زر بارز يفتح نافذة منبثقة (`AddGroupDialog`) فيها
  الفورم كامل (الاسم، السنة، الرسم الشهري، المواعيد الأسبوعية)، بدل ما يكون ظاهر
  وثابت طول الوقت.
- **تعديل كامل**: زر "تعديل" جديد على كل بطاقة يفتح `EditGroupDialog` — بيسمح
  بتعديل **كل حاجة** (الاسم، السنة الدراسية، الرسم الشهري، المواعيد) في مكان واحد،
  بدل ما كان مقصور بس على المواعيد والرسم زي قبل كده.
- **حذف نهائي حقيقي**: زر "حذف نهائي" منفصل تماماً عن "أرشفة" — بعد نافذة تأكيد
  صريحة توضح إن ده **حذف كامل ولا رجعة فيه**، تُحذف المجموعة وكل طلابها وكل
  سجلاتهم (حضور، تقييم، مدفوعات) عبر `db.transaction` واحدة تشمل الجداول الستة.
  الفرق عن "أرشفة" (اللي بتحافظ على البيانات وتخفيها بس) موضَّح صراحةً في نص
  التأكيد نفسه، عشان محدش يحذف بالغلط وهو قاصد يؤرشف.
- الضغط على جسم البطاقة (بره أزرار تعديل/أرشفة/حذف) لسه بيفتح قائمة طلاب المجموعة
  زي ما كان.

### الـ Header العام (`App.jsx`) — بقى شريط واحد رفيع

- اتشال العنوان الكبير المتغيّر لكل شاشة (كان بياخد سطرين ومساحة واضحة).
- بقى الشريط العلوي صف واحد بسيط: **زر القائمة (Menu)** يمين، **اسم العلامة
  "موافي"** في المنتصف بخط صغير، و**زر عودة دائم** يسار — يظهر في كل الشاشات
  ويرجّعك للرئيسية بضغطة واحدة من أي مكان في التطبيق.
- عناوين الشاشات (`title` في `SCREENS`) لسه موجودة ومُستخدَمة في شريط التنقل
  السفلي والقائمة الجانبية بنفس الشكل، بس مش بتتكرر تاني في الـ Header العلوي.

## شاشة الإحصائيات الجديدة (`Statistics.jsx`) + محرّك تقييم مشترك (`scoring.js`)

### توضيح إجابة على سؤالين مهمين قبل الميزة نفسها

- **زر "ابدأ الحصة"**: بيعمل حاجتين بس — يحفظ المجموعة المختارة، وينقلك لشاشة
  "تقييم الحصة" مع هذه المجموعة مُختارة تلقائياً والتاريخ = اليوم. مفيش أي تسجيل
  تلقائي لأي طالب؛ هو فقط بيوفّر عليك خطوة اختيار المجموعة يدوياً.
- **التقييم في شاشة "تقييم الحصة"**: كل تقييم مرتبط بالضبط بـ**(المجموعة + التاريخ)**
  المختارين في رأس الشاشة. مفيش مفهوم "إنهاء حصة" — كل يوم له سجله المستقل تماماً،
  وتغيير التاريخ فوق يعني إنك بتقيّم يوماً مختلفاً كلياً لنفس الطالب.

### محرّك الحساب المشترك (`src/lib/scoring.js`)

استخرجت معادلة الحساب (`computeSessionScore` + `starPoints`) من `Evaluations.jsx`
إلى ملف مشترك جديد، لأن شاشة الإحصائيات محتاجة **تُعيد حساب نفس الدرجة بالضبط**
لعشرات الأيام دفعة واحدة — ولازم تستخدم نفس المعادلة الحقيقية حرفياً (تشمل النقاط
القابلة للتعديل من الإعدادات، ونظام النجوم، والامتحان الاختياري لكل حصة) بدل معادلة
مبسَّطة منفصلة قد تُعطي رقماً مختلفاً عن الدرجة الحقيقية المعروضة فعلياً في شاشة
التقييم لنفس اليوم. أزلت الدالة القديمة `calculateStudentScore` من `db.js` لأنها
كانت معادلة مبسَّطة (50% حضور + 50% مهام بشكل عام) غير متوافقة مع النظام الحالي،
وماكانتش مُستخدَمة في أي مكان أصلاً.

`getStudentDailyScores(studentId, fallbackGroupId)` تجمع كل تواريخ نشاط الطالب
(من الحضور والتقييم معاً)، وتُعيد بناء إعدادات كل يوم (هل كان فيه امتحان؟ الدرجة
النهائية؟) من `db.sessions` باستخدام **المجموعة المسجَّلة فعلياً على سجلات ذلك
اليوم تحديداً** (مش مجموعة الطالب الحالية بالضرورة) — احترازاً لو الطالب اتنقل
بين مجموعات، فتفضل درجاته القديمة صحيحة تاريخياً.

### شاشة الإحصائيات

```jsx
import Statistics from './components/Statistics';

<Statistics
  onDone={() => {
    /* التنقل رجوعاً للوحة التحكم */
  }}
/>;
```

مُدرَجة في القائمة الجانبية. لكل مجموعة مختارة، تعرض قائمة طلابها وبجانب كل طالب:

- **تراكمي كلي**: متوسط تقييم كل الحصص المسجَّلة له منذ أول يوم.
- **تراكمي شهري**: نفس المتوسط لكن مفلتر على الشهر المختار فوق.
- عدد الحصص المسجَّلة له إجمالاً.
- الضغط على أي طالب يفتح **تفاصيل يوماً بيوم** (تاريخ كل حصة + درجتها من 10)،
  عشان تقدر تشوف اتجاه أدائه مش بس متوسط مجرَّد.

## تحسينات رسالة المتابعة + إرسال التقرير التراكمي من الإحصائيات

### 1) اسم المادة في رسالة التقييم

القالب الافتراضي لفئة "متابعة التقييم" بقى فيه سطر "- المادة: [المادة]" من الأساس.

**ملاحظة مهمة لو كنت جربت التطبيق قبل كده**: لأن قوالب الواتساب مُخزَّنة في
`localStorage` جهازك، فلو كان عندك بالفعل قالب افتراضي محفوظ من قبل، مش هيتغيّر
تلقائياً (احتراماً لأي تعديل تكون عملته بنفسك عليه) — التحديث ده بيطبَّق فوراً بس
للمستخدمين الجدد. لإضافة السطر لقالبك الحالي: من الإعدادات ← قوالب الواتساب ←
"متابعة التقييم" ← تعديل القالب الافتراضي ← اضغط شريحة `[المادة]` لإضافتها في مكان
المؤشر. تاخد 10 ثواني.

### 2) الواجب والتفاعل بقوا نصاً وصفياً بدل عدد النجوم في رسالة الواتساب فقط

الواجهة نفسها (نظام النجوم القابل للنقر) **لم تتغيّر إطلاقاً** — لسه بتدخل النجوم
زي ما هي. اللي اتغيّر هو نص الرسالة المُرسَلة لولي الأمر بس:

**الواجب** (`homeworkLabelFromStars`):
| عدد النجوم | النص في الرسالة |
|---|---|
| 0 | لم ينجز |
| أكبر من 0 حتى 2 | أنجز بشكل ضعيف |
| أكبر من 2 حتى 3 | أنجز بشكل جيد |
| أكبر من 3 حتى 5 | أنجز بشكل كامل |

**التفاعل** (`participationLabelFromStars`):
| عدد النجوم | النص في الرسالة |
|---|---|
| 0 | سيئ |
| أكبر من 0 حتى 1 | ضعيف |
| أكبر من 1 حتى 2 | جيد |
| أكبر من 2 حتى 3 | جيد جداً |
| أكبر من 3 حتى 5 | ممتاز |

لو البند "مستثنى"، تفضل الرسالة تقول "مستثنى" بغض النظر عن عدد النجوم، زي ما كان.

### 3) إرسال التقرير التراكمي من شاشة الإحصائيات

أضفت فئة قوالب جديدة **"تقرير تراكمي"** في الإعدادات (بقالب افتراضي جاهز)، مع
متغيرين جديدين: `[الفترة]` و`[التقييم_التراكمي]`. القوالب الموجودة عندك بالفعل
(لو جربت التطبيق قبل كده) هتاخد الفئة الجديدة دي **تلقائياً** بمجرد فتح التطبيق —
دي عملية ترقية آمنة بتضيف بس الفئة الناقصة بدون ما تلمس أي قالب موجود أصلاً.

في `Statistics.jsx`، تحت درجات كل طالب، زران جدد (يظهروا بس لو عنده رقم ولي أمر
ودرجة محسوبة فعلاً — مش قبل ما يكون عنده أي حصص مسجَّلة):

- **"إرسال التراكمي الكلي"**: بيبعت متوسط كل حصصه من أول يوم، الفترة بتظهر
  في الرسالة كـ"بشكل عام".
- **"إرسال تراكمي [اسم الشهر]"**: بيبعت متوسط الشهر المختار فوق تحديداً.

## دمج البيانات بين أجهزة متعددة (`src/lib/merge.js`)

مختلف تماماً عن "استيراد نسخة احتياطية" (اللي بيفرّغ كل البيانات ويستبدلها بالكامل).
"دمج البيانات" **يضيف فقط** ما هو جديد من ملف نسخة احتياطية لبياناتك الحالية،
بدون حذف أو استبدال أي شيء:

- **المجموعات**: تُطابَق بـ(اسم المجموعة + السنة الدراسية). موجودة بالفعل؟ تُتجاهَل.
  جديدة؟ تُضاف برقم `id` جديد على هذا الجهاز.
- **الطلاب**: تُطابَق بـ`qrCode` (فريد لكل طالب بالتصميم أصلاً، فهو مفتاح مثالي للمطابقة).
- **الحضور**: يُطابَق بـ[الطالب المُطابَق + التاريخ] — سجل موجود لنفس اليوم؟ يُتجاهَل.
- **بنود التقييم/المدفوعات/إعدادات الحصص**: نفس المبدأ، كل واحد بمفتاحه الطبيعي
  المناسب ([studentId+date+kind]، [studentId+month]، [groupId+date] على التوالي).
- كل عملية الدمج جزء من `db.transaction` واحدة — إما تكتمل بالكامل أو تفشل بالكامل.
- بعد الدمج تظهر رسالة توضّح بالضبط كام سجل جديد اتضاف في كل جدول.

**سيناريو الاستخدام**: تسجّل حضور/تقييم على الموبايل والتابلت في نفس اليوم؟ صدّر نسخة
من أي جهاز، وادمجها في التاني من الإعدادات ← "دمج البيانات" — مفيش أي بيانات هتضيع.

## تقرير مخصَّص لكل طالب (`Statistics.jsx`)

زر "تقرير" جديد بجانب كل طالب في شاشة الإحصائيات، يفتح نافذة فيها:

- اختيار فترة حرة (من تاريخ لتاريخ، تقدر تمتد لأكتر من شهر بسهولة).
- التقييم التراكمي لهذه الفترة تحديداً في الأعلى.
- جدول تفصيلي يوماً بيوم: التاريخ، حالة الحضور، **اسم المادة** (مسحوبة من إعدادات
  الحصة المسجَّلة فعلياً لهذا اليوم)، ودرجة ذلك اليوم من 10.
- زر "إرسال هذا التقرير لولي الأمر" يبعت ملخصاً (الفترة + المتوسط) عبر واتساب
  باستخدام قالب "تقرير تراكمي" نفسه.

## المظهر — لوحة ألوان ثابتة واحدة (لا يوجد وضع ليلي/نهاري)

جرّبنا إضافة وضع ليلي/نهاري قابل للتبديل، لكن قررنا إزالته بالكامل بناءً على طلب
صريح لتبسيط التطبيق وتفادي أي تعقيد إضافي. التطبيق الآن بلوحة ألوان ثابتة واحدة
فقط: خلفيات بيضاء (`white`) مع درجات بني دافئة (`stone` للنصوص/الحدود، `amber`
للعلامة والأزرار الأساسية) — نفس هوية "أبيض وبني" اللي طُلبت من البداية، لكن بدون
أي زر تبديل أو منطق إضافي.

**ما تمت إزالته بالكامل**:

- زر ووضع "المظهر" من شاشة الإعدادات.
- ملف `src/lib/theme.js` (حُذف تماماً).
- خيار `darkMode` من `tailwind.config.js`.
- كل فئات `dark:` من كل الشاشات (حوالي 400+ فئة تم تنظيفها من كل الملفات).

لو حبيت تضيف الميزة تاني مستقبلاً، أبسط طريقة هي البدء من نظام الألوان الحالي
وإضافة `dark:` variants تدريجياً شاشة بشاشة، مع التأكد من عمل `npm run dev`
بالكامل من جديد (وليس Hot Reload) بعد أي تعديل في `tailwind.config.js`.

## إصلاحات UX إضافية

### 1) مؤشر الماوس (Cursor) للعناصر القابلة للنقر

بدل ما نحتاج نكرر `cursor-pointer` يدوياً على كل زر في كل شاشة (كانت المتصفحات

### 2) "الحصص القادمة" — التاريخ والميعاد أسفل شارة "متبقي"

كان التاريخ/الميعاد النسبي يظهر بس تحت اسم المجموعة، وشارة "متبقي كذا" لوحدها
بدون سياق. دلوقتي شارة "متبقي" (أو زر "ابدأ الحصة" لو الحصة شغّالة) بقى تحتها
مباشرة نص صغير بالتاريخ والميعاد الفعلي (مثلاً "اليوم — 7:00 م")، فكل عنصر في
القائمة بقى مفهوم لوحده بنظرة واحدة.

### 3) "إجراءات سريعة" في لوحة التحكم — أيقونات بدل نص

القسم كان قائمة أزرار نصية طويلة (تصدير JSON، تصدير CSV، أرشفة). بقى شبكة من
8 أزرار أيقونات (`QuickActionIcon`) — كل زر أيقونة دائرية + تسمية صغيرة تحتها،
بنفس روح أيقونات شريط التنقل السفلي: تصدير JSON، تصدير CSV، أرشفة، المجموعات،
إضافة طالب، المالية، الإحصائيات، الإعدادات — كل واحد بيوديك للشاشة المناسبة
مباشرة (عبر props جديدة زي `onGoToGroups`, `onGoToAddStudent`, `onGoToSettings`,
`onGoToFinance`, `onGoToStatistics` مُمرَّرة من `App.jsx`).

## تحديث جوهري لنظام التقييم — 5 تعديلات مترابطة

### 1) الغياب يأخذ نقاط بالسالب فعلياً

قبل كده: الغياب كان يعطي صفر نقاط لبند الحضور (محايد). دلوقتي: الغياب يعطي **نفس
وزن الحضور لكن بالسالب** — عقوبة حقيقية تقلّل التقييم النهائي فعلياً، مش مجرد
"عدم كسب نقاط". القيمة النهائية المعروضة لولي الأمر لسه محدودة بين 0 و10 (مينفعش
تظهر درجة سالبة مربكة)، لكن الحساب الداخلي (`earned`) بيعكس العقوبة الحقيقية، فلو
كانت كبيرة كفاية هتوصل الدرجة لصفر فعلاً بدل ما تفضل مرتفعة بشكل غير منطقي.
التعديل في `computeSessionScore` بملف `src/lib/scoring.js` — مطبَّق تلقائياً في كل
مكان يستخدم هذه الدالة (شاشة التقييم + الإحصائيات).

### 2) بند جديد: "التسميع" + إمكانية تفعيل/تعطيل الواجب والتسميع والتفاعل لكل حصة

- أضفت **"التسميع"** كبند تقييم خامس مستقل (نظام نجوم من 5 زي الواجب والتفاعل
  بالظبط)، بوزن افتراضي 2 نقطة قابل للتعديل من الإعدادات.
- **الأهم**: الواجب والتسميع والتفاعل بقوا الآن قابلين للتفعيل/التعطيل **لكل حصة
  على حدة**، بنفس آلية "هل يوجد امتحان؟" تماماً — 4 مفاتيح تبديل في رأس شاشة
  التقييم (امتحان/واجب/تسميع/تفاعل). لو عطّلت بند معيّن ليوم بعينه، نقاطه القصوى
  ما بتدخلش في "المتاح" لهذه الحصة أصلاً، وحقله بيختفي من أمام كل الطلاب.
- ده بيحل مشكلة حقيقية: يوم مفيش فيه واجب أو تسميع، مكنش المدرس مضطر يسجّل صفر
  (اللي كان بيأثر سلباً على التقييم ظلماً) — دلوقتي ببساطة يعطّل البند لهذا اليوم.

### 3) الحضور: أزرار متجاورة بدل قائمة منسدلة

في شاشة التقييم، حقل "الحضور" لكل طالب بقى 3 أزرار متجاورة (حاضر/غائب/مستثنى)
بدل `<select>`، بألوان مميزة (أخضر/أحمر/كهرماني) — أسرع بالضغط بإصبع واحد على
الموبايل، ومفيش حاجة تتخبى جوه قائمة منسدلة.

### 4) تقرير الإحصائيات المُوسَّع

نافذة "تقرير" لكل طالب في شاشة الإحصائيات بقت تعرض (كل ده مرتبط بفلتر المادة
والفترة المختارين):

- **فلتر المادة** (يظهر فقط لو عندك مواد معرَّفة من الإعدادات) — "كل المواد" أو
  مادة بعينها، فتقدر تشوف أداء الطالب في "فقه" لوحدها مثلاً بمعزل عن باقي المواد.
- **عدّادات الحضور**: كام حصة حضرها، كام غاب عنها، كام كانت مستثناة.
- **متوسط كل بند لوحده من 5**: الواجب، التسميع، التفاعل — كل واحد بمتوسطه
  المستقل (محسوب فقط من الأيام اللي فعلاً اتسجَّل فيها البند، مش الأيام اللي كان
  فيها معطَّل أصلاً).
- **قائمة الامتحانات**: كل امتحان دخله الطالب بتاريخه ودرجته (score/total)، مش
  بس متوسط عام.
- التقييم التراكمي العام للفترة + الجدول اليومي التفصيلي لسه موجودين زي ما كانوا.

### 5) استثناء شهر كامل من التقييم التراكمي لطالب معيّن

من شاشة "طلاب المجموعة" ← تعديل بيانات أي طالب ← قسم جديد "استثناء أشهر من
التقييم التراكمي": تقدر تضيف شهر (أو أكتر) بحيث **لا يُحتسَب هذا الشهر إطلاقاً**
ضمن متوسطات الطالب التراكمية (الكلي والشهري) ولا في تقرير الإحصائيات — مفيد لو
الطالب انضم متأخراً أو غاب لظرف طارئ طول الشهر ومش عايز الشهر ده يجرّ متوسطه
لأسفل ظلماً. البيانات نفسها (حضور/تقييم) **بتفضل محفوظة كاملة** — الاستثناء بس
في الحسابات التجميعية، ومقدور تلغيه في أي وقت.

## تصحيح: "استثناء شهر" كانت لازم تكون إعفاء من المصروفات، مش من التقييم

في الأول فهمت طلب "استثناء من الشهر" على إنه استثناء من **التقييم التراكمي**،
لكن الطلب الحقيقي كان استثناء من **دفع المصروفات**. عالجت الاثنين كميزتين منفصلتين
وواضحتين تماماً بأسماء مختلفة، حتى ما يحصلش لبس زي اللي حصل:

### أ) "استثناء أشهر من التقييم التراكمي" (الميزة الأصلية، لسه موجودة زي ما هي)

من تعديل بيانات الطالب — شهر مُستثنى هنا يعني إنه مش هيُحتسَب ضمن متوسط تقييمه
التراكمي في شاشة الإحصائيات. لا علاقة له بالمصروفات إطلاقاً.

### ب) "إعفاء من مصروفات شهر" (الميزة الجديدة المطلوبة فعلياً)

قسم منفصل تماماً أسفل قسم استثناء التقييم مباشرة، في نفس شاشة تعديل بيانات الطالب:

- حقل جديد على الطالب: `feeExemptMonths` (مصفوفة شهور بصيغة `YYYY-MM`، حقل عادي
  غير مفهرَس، بدون أي تعديل Dexie schema).
- **شاشة المدفوعات**: الطالب المُعفى عن الشهر المختار يظهر بشارة رمادية "معفى هذا
  الشهر" بدل حقل إدخال المبلغ وزر "تسديد" — ومش بيتحسب ضمن "متأخرين عن الدفع" في
  لوحة التحكم (`getLatePaymentStudents` في `db.js` بقت تتجاهله تلقائياً).
- **شاشة المالية**: "المتوقَّع تحصيله" لكل مجموعة بقى محسوباً من الطلاب غير
  المُعفَين فقط (`الرسم الشهري × عدد الطلاب غير المعفَين`)، فمعفى شهر واحد مش
  بيرفع رقم "المتوقَّع" ظلماً. بطاقة كل مجموعة بتعرض كمان عدد المعفَين (لو موجود)
  بجانب "كام دفعوا" للشفافية.
- الطالب لسه ظاهر طبيعي في كل القوائم — الإعفاء مجرد استثناء من حسابات "متأخر
  عن الدفع" و"المتوقَّع تحصيله"، مش إخفاء أو حذف لأي بيانات.

## تحديد متعدد + إجراءات جماعية + إرسال متسلسل للواتساب

### تحديد متعدد في شاشة التقييم

كل صف طالب في `Evaluations.jsx` بقى فيه Checkbox، مع خيار "تحديد الكل" فوق
القائمة. بمجرد ما تحدد طالب واحد على الأقل، يظهر **شريط إجراءات جماعي** ثابت
أسفل الشاشة فيه:

- تعليم حاضر / غائب / مستثنى للكل دفعة واحدة.
- (لو الواجب مفعّل لهذه الحصة) الكل: واجب كامل / الكل: لم ينجز الواجب.
- (لو التسميع مفعّل) الكل: تسميع كامل.
- (لو التفاعل مفعّل) الكل: تفاعل ممتاز.

كل زر بيطبّق التغيير على كل الطلاب المحدَّدين عبر `Promise.all` (كتابة متوازية
سريعة في Dexie). التحديد بيتصفّر تلقائياً لو غيّرت المجموعة أو التاريخ، تفادياً
لتطبيق إجراء بالغلط على سياق مختلف.

### إرسال تقارير لأكتر من طالب — التوضيح المهم

**واتساب نفسه لا يدعم إرسال رسالة لأكتر من رقم واحد في ضغطة واحدة** عبر روابط
`wa.me` — هذا قيد من واتساب مش من التطبيق، ومفيش طريقة تقنية شرعية لتجاوزه بدون
WhatsApp Business API (خارج نطاق تطبيق Offline بالكامل زي ده).

**أفضل بديل عملي بنيته**: من شاشة الإحصائيات، حدّد أكتر من طالب (نفس آلية
Checkbox)، واضغط "إرسال تقارير لـ N طالب" — تفتح نافذة **إرسال متسلسل**:
تعرضلك "طالب 1 من N" مع زر "فتح واتساب لهذا الطالب" (الرسالة جاهزة بالتقييم
التراكمي الكلي)، وبعد ما ترسلها يدوياً في واتساب، ترجع للتطبيق وتضغط "التالي"
فينقلك لبيانات الطالب اللي بعده مباشرة بدون ما تدوّر عليه تاني من الأول. أسرع
بكتير من التنقل اليدوي بين كل طالب لوحده، لكنه مش "ضغطة واحدة ترسل للكل" لأن ده
مستحيل تقنياً بالطريقة دي.

## الوصول للباركود في أي وقت (`StudentCard.jsx`)

- استخرجت تصميم الكارنيه (رسم QR + الطباعة + الحفظ كصورة) من `AddStudent.jsx` إلى
  مكوّن مشترك جديد `StudentCard.jsx`، بدل ما يكون منطقه مكرَّراً في كل مكان محتاج
  يعرض الكارنيه.
- **الوصول من "طلاب المجموعة"**: زر "الكارنيه" جديد على كل صف طالب (بجانب تعديل/
  أرشفة/حذف) يفتح نافذة فيها نفس الكارنيه بالضبط — طباعة أو حفظ كصورة، في أي وقت،
  بدون الحاجة للمرور بشاشة "إضافة طالب" تاني. مفيد لو الكارنيه اتكسر أو المدرس
  محتاج ينسخة إضافية لطالب موجود بالفعل.
- `AddStudent.jsx` نفسها بقت تستخدم نفس المكوّن المشترك بدل نسخة منفصلة، فأي
  تحسين مستقبلي على تصميم الكارنيه (لون، تخطيط) هيطبَّق تلقائياً في كل الأماكن
  دفعة واحدة.

## البحث السريع عن طالب + تصدير PDF + تقوية إعدادات النقاط

### 1) البحث السريع (`App.jsx`)

أيقونة بحث جديدة في الـ Header (بين المنيو وزر الرئيسية). بمجرد الكتابة، يظهر
حتى 8 نتائج مطابقة (اسم الطالب يحتوي النص المكتوب) مع اسم مجموعة كل واحد. الضغط
على أي نتيجة:

- ينقلك مباشرة لشاشة "إدارة المجموعات"
- يفتح تلقائياً قائمة طلاب **المجموعة الصحيحة** لهذا الطالب تحديداً (بدون ما
  تدوّر عليها بنفسك)
- يبرز (Highlight) صف الطالب بلون كهرماني ويعمل Scroll تلقائي له

البيانات (كل الطلاب + كل المجموعات) محمَّلة بخفة دايماً في الخلفية عبر
`useLiveQuery` في `App.jsx` نفسها (بيانات نصية بسيطة، مش أعباء حقيقية) عشان
البحث يكون فوري بدون أي تأخير أو استعلام إضافي وقت الكتابة.

### 2) تصدير تقرير الإحصائيات كـ PDF (`Statistics.jsx`)

زر "تصدير PDF" جديد في نافذة "تقرير" — **ملاحظة تقنية مهمة**: بدل استخدام مكتبة
PDF جافاسكريبت (زي jsPDF أو pdf-lib)، استخدمت أسلوب "طباعة المتصفح" (نفس الأسلوب
المُستخدَم بالفعل لطباعة كارنيه QR). السبب: مكتبات PDF في JavaScript **لا تدعم
تشكيل الحروف العربية تلقائياً** (شكل الحرف العربي يتغيّر حسب موضعه في الكلمة —
أول/وسط/آخر/منفصل)، بينما محرك عرض المتصفح نفسه يفعل هذا بشكل مثالي من غير أي
إعداد إضافي. الزر بيفتح صفحة تقرير منسَّقة بالكامل (ملخص + عدّادات + متوسطات
البنود + الامتحانات + الجدول اليومي)، وتضغط "طباعة / حفظ كـ PDF" فيفتح مربّع
طباعة المتصفح القياسي، وتختار "حفظ كـ PDF" كوجهة — مدعومة افتراضياً في كل
المتصفحات الحديثة على الموبايل وسطح المكتب.

### 3) تقوية `loadPointsSettings` ضد أي بيانات محفوظة قديمة جزئياً

لو نسخة قديمة من `points.js` كانت محفوظة عندك في `localStorage` قبل إضافة بند
"التسميع"، الدمج القديم بين الإعدادات المحفوظة والافتراضية كان بالـ spread
المباشر، وده كان المفروض يشتغل صح فعلياً، لكن قوّيته أكتر باستبدال الدمج بفحص
كل بند على حدة (`typeof saved[key] === "number"`) — أي بند غير رقمي أو غير
موجود إطلاقاً في المحفوظ القديم يرجع لقيمته الافتراضية تلقائياً، بدل أي احتمال
لقيمة `undefined` تفلت من الحساب بصمت.

## ملاحظات مهمة

- **isArchived** مخزّن كـ `0` أو `1` (وليس `true/false`) لأن Dexie يفهرس القيم البدائية
  بشكل أفضل مع `.equals()`. الـ hooks في `db.js` تتكفل بالقيمة الافتراضية تلقائياً.
- **QR Code**: `db.js` يولّد حقل `qrCode` فريد تلقائياً عند إضافة أي طالب جديد
  (جاهز لتمريره لأي مكتبة توليد QR مثل `qrcode.react`، ولأي مكتبة قراءة كاميرا
  مثل `html5-qrcode` أو `@zxing/browser` عند بناء شاشة تسجيل الحضور).
- **حساب التقييم** (`calculateStudentScore`) يستثني تلقائياً أي سجل حضور أو مهمة
  محدد عليها `Excused` / `isExcused: true` من المعادلة، بحيث لا تؤثر على النتيجة النهائية.
- **تذكير النسخ الاحتياطي** يُخزَّن تاريخ آخر نسخة في `localStorage` تحت المفتاح
  `cms_last_backup_at`، ويظهر تنبيه تلقائي كل 7 أيام في أعلى لوحة التحكم.
- **رابط الواتساب** يُستخدم فيه `wa.me` مباشرة (بدون أي API خارجي)، وهو يفتح تطبيق
  واتساب على جهاز المدرس مع رسالة جاهزة، وهذا يعمل من المتصفح ومن تطبيق PWA.

## الخطوات التالية المقترحة

1. شاشة "إضافة طالب" باستخدام `react-hook-form` + توليد QR عبر `qrcode.react`.
2. شاشة "بدء حصة" لمسح QR عبر الكاميرا (`html5-qrcode`) وتسجيل الحضور دفعة واحدة.
3. شاشة "الأرشفة" لتحديث `isArchived = 1` على مجموعة كاملة وطلابها دفعة واحدة
   (استخدم `db.transaction()` لضمان التناسق).
4. تسجيل Service Worker (عبر `next-pwa` إن استخدمت Next.js) لجعل التطبيق يعمل
   بدون إنترنت بالكامل حتى عند تحميل الصفحة أول مرة.
